Програмиране - Обработка на списък с цени и наличности. Практическа задача

Ще използваме няколко едномерни структури за различни данни на едни и същи стоки. Съответствието се определя от позицията.

1. Съответстващи индекси

Паралелни структури са поредици, при които един и същ индекс описва един обект. names[i] е името, prices[i] — единичната цена, stocks[i] — наличното количество на една и съща стока. Дължините трябва да съвпадат и редът трябва да е общ.

В C# string[] е масив от текстове, както int[] е масив от цели числа. В примера цените са цели парични единици, а наличностите — неотрицателни цели бройки.

2. Намери изчерпаните стоки и стойността

Първо проверяваме дължините. Изчерпаните стоки имат наличност 0. Общата стойност е сбор от цена по наличност; за малките учебни стойности резултатът се побира в int.

Python

names = ["Тетрадка", "Папка", "Молив"]
prices = [5, 8, 3]
stocks = [0, 2, 0]
if (len(names) != len(prices)) or (len(names) != len(stocks)):
    print("Различни дължини")
else:
    total = 0
    for i in range(len(names)):
        if stocks[i] == 0:
            print(names[i], prices[i])
        total = total + prices[i] * stocks[i]
    print("Стойност:", total)

C#

using System;

string[] names = new string[]
{
    "Тетрадка", "Папка", "Молив"
};
int[] prices = new int[] { 5, 8, 3 };
int[] stocks = new int[] { 0, 2, 0 };
if ((names.Length != prices.Length)
    || (names.Length != stocks.Length))
{
    Console.WriteLine("Различни дължини");
}
else
{
    int total = 0;
    for (int i = 0; i < names.Length; i = i + 1)
    {
        if (stocks[i] == 0)
        {
            Console.Write(names[i]);
            Console.Write(" ");
            Console.WriteLine(prices[i]);
        }
        total = total + prices[i] * stocks[i];
    }
    Console.Write("Стойност: ");
    Console.WriteLine(total);
}

Изход на двете програми:

Тетрадка 5
Молив 3
Стойност: 16

3. Защо еднаквите дължини не са достатъчни?

Проверката предотвратява достъп извън края, но не доказва, че стоките са в еднакъв ред. Ако разменим само две имена, цените и наличностите вече ще бъдат приписани на други стоки. Трябва да пазим съответствието при всяка промяна.

4. Промяна и проверка

Ако наличността на „Тетрадка“ стане 3, променяме stocks[0], а не цената. След това преизчисляваме общата стойност чрез ново обхождане. Няма автоматична връзка, която сама да обнови вече пресметнатия total.

Можем да приложим и съставен критерий, например цена до 5 и положителна наличност. Двете проверки трябва да използват един и същ индекс.

5. Самостоятелни задачи

  1. Промени stocks[0] на 3 и предвиди общата стойност.
  2. Какво става при различни дължини?
  3. Изведи само стоки с положителна наличност и цена <= 5.
  4. Защо не бива да подреждаш само масива names?
Отговори и насоки
  1. Стойността става 31; „Тетрадка“ вече не е изчерпана.
  2. Показва се „Различни дължини“ без обхождане по невалидни позиции.
  3. Условието е stocks[i] > 0 И prices[i] <= 5. За началните данни няма такива стоки.
  4. Ще се наруши съответствието с цените и наличностите.

Запомни: Общият индекс свързва данните. Пази еднакви дължини и еднакъв смисъл на всяка позиция.
