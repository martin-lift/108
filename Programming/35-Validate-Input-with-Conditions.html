Програмиране - Проверка на входни данни чрез условни конструкции. Упражнение

Ще използваме условия, за да различаваме допустими и недопустими стойности, преди да извършим изчисление.

1. Правилен запис и допустима стойност

Както в урок 25, валидният числов запис не гарантира, че стойността е подходяща. −3 се преобразува в int, но не е допустим брой предмети. Тук приемаме вход, който е коректен запис на цяло число, и проверяваме неговия диапазон. Нечисловият текст все още би предизвикал грешка при Parse или int.

Първо прочитаме, после проверяваме, и едва в допустимия клон пресмятаме. Съобщението за невалиден вход трябва да обяснява какво се изисква.

2. Провери диапазона 0–100

Границите се включват. Съставното условие е от урок 32, а изборът на съобщение е if/else.

Въведи последователно: 0. След всяка стойност натисни Enter.

Python

score = int(input())
if (score >= 0) and (score <= 100):
    print("Допустимо")
else:
    print("Въведи число от 0 до 100")

C#

using System;

int score = int.Parse(Console.ReadLine() ?? "");
if ((score >= 0) && (score <= 100))
{
    Console.WriteLine("Допустимо");
}
else
{
    Console.WriteLine("Въведи число от 0 до 100");
}

Изход на двете програми:

Допустимо

3. Провери делителя преди деление

Задачата е за остатъка от 12 при положителен делител. Нулата и отрицателните стойности водят до съобщение. Операцията е вътре в допустимия клон; не я пресмятаме преди проверката.

Въведи последователно: 0. След всяка стойност натисни Enter.

Python

divisor = int(input())
if divisor <= 0:
    print("Делителят трябва да е положителен")
else:
    print(12 % divisor)

C#

using System;

int divisor = int.Parse(Console.ReadLine() ?? "");
if (divisor <= 0)
{
    Console.WriteLine("Делителят трябва да е положителен");
}
else
{
    Console.WriteLine(12 % divisor);
}

Изход на двете програми:

Делителят трябва да е положителен

4. Планирай тестовете

ИзискванеПодходящи тестове
Поне 1 предмет0, 1, 2
От 0 до 100−1, 0, 100, 101
Ненулев делител0 и допустима ненулева стойност

Тестът точно на границата открива объркване между > и >=. Недопустимата стойност трябва да доведе до съобщение, а не до използване на неполучен резултат. Тази програма проверява веднъж; повторното въвеждане ще изисква цикъл по-късно.

5. Самостоятелни задачи

  1. Провери положителен брой артикули и изведи обща цена само при допустим брой.
  2. Проследи програмата за делител при −5, 1 и 5.
  3. Защо проверка след вече извършено деление не предпазва от нула?
  4. Избери тестове за процент отстъпка от 0 до 100.
Отговори и насоки
  1. Използвай quantity > 0; иначе покажи изискването.
  2. Съобщение за положителен делител; остатък 0; остатък 2.
  3. Опасната операция вече е била изпълнена.
  4. −1, 0, 100, 101 и обичайна стойност като 20.

Запомни: Проверявай преди действието и изпълнявай изчислението само когато данните отговарят на условието.
