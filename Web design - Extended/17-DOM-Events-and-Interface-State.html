JavaScript — DOM, събития и състояние на интерфейса

Всички предметиУеб дизайн - СППУеб дизайн - Учебна практикаУеб дизайн - Разширена подготовка

След урока ще можете да:

  • намирате елемент в DOM по неговия идентификатор;
  • свързвате действие на потребителя със събитие;
  • поддържате съгласувани текст, видимост и състояние на бутон.

1. HTML и дървото DOM

След обработването на HTML браузърът представя документа като дърво от обекти — DOM. JavaScript може да намери елемент и да промени текста, атрибутите или класовете му. Това е промяна в текущата страница; тя не записва автоматично изходния HTML файл.

Използвайте уникални идентификатори. Ако търсеният елемент липсва, getElementById връща null. Проверете изписването и дали кодът се изпълнява след създаването на елемента, например със script в края на body.

2. Събитие и обработчик

click съобщава за активиране на бутон, input — за промяна при въвеждане, а submit — за опит за изпращане на форма. С addEventListener свързваме събитието с функция.

При калкулатора събитието води до прочитане, проверка и изчисление. При смяна на тема обработчикът сменя CSS клас. При учебна форма preventDefault() може да спре изпращането, но сам по себе си не валидира данните.

3. Състоянието трябва да се вижда

Състоянието е информация като „панелът е отворен“ или „темата е тъмна“. След действие съгласувайте всички свързани елементи: видимостта, надписа на бутона и aria-expanded. Иначе бутонът може да твърди „Покажи“, въпреки че съдържанието вече се вижда.

За обикновен текст използвайте textContent. Не вмъквайте въведено от посетител съдържание като HTML. Изпробвайте поредица от действия, а не само първото натискане.

Пример

const button = document.getElementById("toggle-info");
const panel = document.getElementById("info-panel");
button.addEventListener("click", () => {
  panel.hidden = !panel.hidden;
  button.setAttribute("aria-expanded", String(!panel.hidden));
  button.textContent = panel.hidden ? "Покажи пояснението" : "Скрий пояснението";
});

Изпробвайте

Променихте състоянието на панела чрез събитие click. При следващо активиране панелът отново ще се скрие.

Практическа задача

  1. Натиснете бутона три пъти и запишете след всяко действие видимостта и надписа.
  2. Сравнете aria-expanded с действителното състояние чрез разрешените инструменти на браузъра.
  3. Добавете същия панел в проекта си с различни уникални идентификатори.
  4. Изпробвайте го с клавиатура. Добавете отделен бутон за смяна на тема чрез CSS клас.
  5. Опишете какви събития използват калкулаторът и проверката на форма от учебната практика.

Предавате: работещ HTML файл и таблица с три последователни проверки на състоянието.

Самопроверка

Промяната в DOM записва ли HTML файла?

Не. За трайна промяна редактираме и записваме изходния файл.

Какво означава aria-expanded=true?

Свързаното разгръщащо се съдържание е показано. Атрибутът трябва да отразява действителната видимост.

Кой избор е подходящ за обикновено съобщение?

textContent, когато искаме текст, а не нов HTML код.
